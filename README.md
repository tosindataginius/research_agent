## 🤖 Autonomous Research Assistant Agent

An autonomous, multi-agent AI system designed to conduct deep research on any given topic. The system orchestrates multiple specialized AI agents to construct a research plan, gather credible web sources, analyze findings, synthesize a comprehensive Markdown report, and compile the final output into a downloadable PDF document.

Built using **Python, LangChain** and powered by the **Google Gemini API.**

This project also features both a production-ready **FastAPI Backend** (with structural concurrency and LangSmith execution tracing) and an intuitive **Streamlit Web Frontend**.

---

## Architecture & Agent Workflow

The platform utilizes a sequential multi-agent orchestration pattern to split complex objectives into clear, manageable steps:

[User Input] ➔ [Planner Agent] ➔ [Search Service] ➔ [Researcher Agent] ➔ [Writer Agent] ➔ [PDF Export]



1. **Planner Agent (`agents/planner.py`)**: Explodes the core topic into a structured research outline.
2. **Search Service (`services/search.py`)**: Scrapes and aggregates factual web resources matching the topic queries.
3. **Researcher Agent (`agents/researcher.py`)**: Extracted core analytical insights and facts directly from gathered sources.
4. **Writer Agent (`agents/writer.py`)**: Compiles raw findings into an academic or business-grade report with accurate citations.
5. **PDF Export Service (`services/pdf_export.py`)**: Converts the final text report into a clean, downloadable PDF format.

---

## Key Features

* **Dual Interface Support**: Use the UI interface via Streamlit or integrate programmatically using the FastAPI endpoints.
* **Persistent Session State**: Streamlit frontend uses `st.session_state` to prevent data loss or duplicate API triggers during PDF downloads.
* **Production Concurrency**: FastAPI backend utilizes `asyncio.to_thread` execution wrappers to prevent synchronous LLM bottlenecks from stalling the event loop.
* **Observability with LangSmith**: Deep context integration using `RunTree` lets you profile latency, token counts, and step-by-step logic paths inside your LangSmith dashboard.
* **Defensive Error Handling**: Isolated `try-except` layers catch bad payloads, service timeouts, or filesystem anomalies without crashing the host processes.

**The Entry PointUser Query**
The human operator inputs a high-level research goal or question (e.g., "Analyze the commercial growth of Solid-State Batteries in 2026").

**The Planning PhasePlanner**
A specialized LLM receives the raw query. Its sole job is to break down the large topic into a granular blueprint. 
It identifies specific sub-topics, questions, and parameters that need to be investigated to make the final report comprehensive.

**The Retrieval Phase (RAG)Search + URLs**
The system takes the plan generated by the Planner and programmatic search queries are fired off via API (like Google Search, Tavily, or Serper). 
This step scrapes live data from the web and returns a list of target URLs and raw web text blocks.

**The Deep Synthesis PhaseResearch Agent**
This LLM acts as the core analyst. 
It receives the curated web text along with a strict system prompt instructing it to ignore its pre-training weights and only use the data found in the retrieved web documents. 
It cross-references facts and structures raw textual findings.

**The Grounding PhaseCitation Builder**
This code or helper script organizes the source links. It assigns exact numerical identifiers (like [1], [2]) to each URL and wraps them tightly into blocks. This forces the downstream model to stick to a verifiable paper trail and prevents data formatting loss.

**The Compilation & Delivery PhaseWriter**
A creative, stylistically-polished LLM takes the raw factual data from the Research Agent and the structured URLs from the Citation Builder. 
It stitches everything into a formal, structured document with traditional corporate sections (Executive Summary, Findings, References).
PDF Export: Python code (using tools like ReportLab or FPDF) converts the text/markdown output from the Writer into a clean, unalterable business document.

**Download**
The backend API hands a finalized, downloadable binary stream (.pdf file) back to the user's interface.

## Setup & Installation

### 1. Clone the Repository
```bash
git clone https://github.com
cd your-repo-name
```

### 2. Set Up a Virtual Environment
```bash
python -m venv venv
source venv/bin/activate  # On Windows use: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Environment Variables & Secrets
Create a `.env` file in the root directory for your API credentials (e.g., OpenAI, Search Engine API keys, LangSmith):

```env
OPENAI_API_KEY=your_openai_api_key
SEARCH_API_KEY=your_search_provider_key
LANGCHAIN_TRACING_V2=true
LANGCHAIN_API_KEY=your_langsmith_api_key
LANGCHAIN_PROJECT=Autonomous-Research-Assistant
```

For the Streamlit frontend, you can also store these locally in `.streamlit/secrets.toml`:
```toml
LANGCHAIN_API_KEY = "your_langsmith_api_key"
LANGCHAIN_PROJECT = "Autonomous-Research-Assistant"
```

## 📡 API Reference Documentation

### 1. Execute Research Pipeline
* **Endpoint**: `POST /api/research`
* **Payload Structure (`Content-Type: application/json`)**:
```json
{
  "topic": "The impact of quantum computing on modern cryptography"
}
```
* **Response Structure (`200 OK`)**:
```json
{
  "topic": "The impact of quantum computing on modern cryptography",
  "research_plan": "...(Markdown generated plan)...",
  "sources": [
    {"title": "Example Academic Paper", "url": "https://example.com"}
  ],
  "findings": "...(Extracted agent data)...",
  "report": "...(Final compiled markdown report)...",
  "pdf_path": "/absolute/path/to/generated/Research_Report.pdf"
}
```

### 2. Fetch Compiled PDF Report
* **Endpoint**: `GET /api/download-pdf`
* **Query Parameter**: `?file_path=/absolute/path/to/generated/Research_Report.pdf`
* **Response**: Binary stream containing the generated PDF attachment.
